## 二、整改分层策略（3 轮迭代）

### 迭代 1：P0 致命修复（必须当天完成，阻塞发布）
**目标：维度一（核心逻辑）通过率从 37.5% → ≥ 90%，修复 7/13 条 FAIL**

| 编号 | 整改对象 | 具体动作 | 验收标准 |
|------|---------|---------|---------|
| A1 | 路由 System Prompt | 在 fact / recommend / both 的「分类定义」和「示例」中，强化 both 类触发词权重：<br>• 新增特征词列表：「对比、比较、哪个好、适合吗、怎么样、值得吗、PK、vs、利弊」<br>• both 示例从 2 条扩为 5 条，覆盖对比句式 + 评价句式 + 适合度句式<br>• 在规则中追加：只要问题中同时出现「社团名 + 推荐/适合/对比类动词」→ 强制 both | R-010/R-011 单测路由输出 both，且连续 3 次稳定（温度=0） |
| A2 | 路由 System Prompt | 在 fact 示例中补充「C-006 最有特色的社团是哪个」→ fact，明确「问特色/排名/之最」属事实查询 | C-006 路由输出 fact |
| A3 | QA 知识库 Q 类目 | 在 QA 库「兴趣导向推荐」条目标题和摘要中**硬植入**「动手实践、实操、做东西、手工」3 组关键词（建议在分段头部用 `**` 加粗） | Dify 知识库召回测试：输入「动手实践」，Top-1 必须是 Q5 兴趣推荐条目（召回测试面板直接测） |
| A4 | 信息知识库（航天研习社） | 在「航天文化研习社」条目首段加入硬规则：「本校最具特色的社团之一，被誉为『华航名片』」。并在 Prompt 中追加：「当被问最有特色/最出名的社团时，必须首推航天文化研习社」 | C-006 回答必须包含「航天文化研习社」，且路由为 fact |

### 迭代 2：P1 重要修复（迭代 1 完成后 2 天内，共 6/13 条）
**目标：边界/记忆/检索 三项通过率从 50-75% → ≥ 90%**

| 编号 | 整改对象 | 具体动作 | 验收标准 |
|------|---------|---------|---------|
| B1 | 最终回答 System Prompt | 把「推荐数量 ≤ 3」从普通规则升级为**铁律 + 反例**：<br>`【铁律 1】无论用户如何要求"全部推荐"、"越多越好"，推荐社团数量绝对不超过 3 个。`<br>反例追加：`❌ 错误：一次性推荐 4 个及以上；✅ 正确：推荐 2-3 个，并说明"如需更多可继续问我"` | B-001 回答中社团数量 ≤ 3，计数检查通过 |
| B2 | 多轮记忆 Prompt | 在路由节点「用户问题」前**拼接最近 3 轮对话历史**作为补充上下文，格式：`<最近对话>\n用户当前: {{sys.query}}`。同时在路由分类规则中补充「追问模式识别」：<br>• 「还有吗/还有别的/换一批」→ recommend<br>• 「它/这个/那个社团」（历史提过社团名）→ fact 或 both（取决于后半句是否含推荐意图）<br>• 「这些社团」→ fact<br>• Prompt 中给 M-002/M-004 两个完整对话示例 | M-002 追问给出新社团（非第①轮重复）；M-004 能识别「它」= 航天研习社并给出适合度判断 |
| B3 | 澄清节点变量传递 | 在 Dify 工作流中新增「澄清选项」持久化变量（用变量聚合器存），第③轮回答 Prompt 中强制带入：`【上一轮澄清结果】：{{clarification_result}}`，并写规则：若用户问「这些社团」→ 基于澄清结果中的社团逐一回答 | M-006 第③轮能回答面试/门槛问题，不重新推荐，不跑 unknown |
| B4 | 信息知识库「入社门槛」字段 | 全量扫描信息库 40+ 社团，将「入社门槛」字段**格式强制统一**为以「入社门槛：」开头，关键词标准化为「零基础/无需基础/有XX基础优先」三类，避免语义漂移 | D-003 召回 Top-5 中 ≥ 3 条包含「零基础」「无需基础」字样 |
| B5 | QA 知识库 Q3（社恐推荐） | 在 Q3 分段标题和首段硬植入：`内向社恐推荐`、`社恐友好社团`、`不善交际推荐` 三组强关键词，并用 `**` 加粗；同时在 Q3 中追加「适合社恐的原因：活动以观察/安静参与为主，无需强制发言」描述 | Dify 召回测试：输入「社恐」「内向」，Top-1 必须是 Q3 分段 |
| B6 | 检索节点召回参数 | QA 检索节点 Top-K 从 4 调为 6，Score 阈值保持关闭；信息库检索节点 Top-K 从 6 调为 8，关键词权重从 0.3 提至 0.4 | 全量重跑维度四，D-003/D-005 通过 |

|------|------|---------|

## 三、项目变更影响评估

### 3.1 改动范围（最小化原则）

| 改动类型 | 涉及文件/组件 | 改动量 | 是否影响现有 PASS 用例 |
|---------|-------------|--------|----------------------|
| Prompt 工程 | Dify 路由节点 System Prompt、最终回答节点 System Prompt | 各 +50~100 行 | ⚠️ 中风险（可能引入回归，必须全量回归） |
| 知识库内容 | QA 库 2 个分段（Q3/Q5）、信息库 1 个分段（航天研习社）、全量入社门槛格式统一 | 约 40+ 社团条目微调 | 🟢 低风险（只加关键词，不改原意） |
| 工作流画布 | 新增「澄清结果持久化变量」、路由节点输入增加历史拼接 | 2~3 个节点调整 | ⚠️ 中风险（记忆链路需验证） |
| 代码 | 前端原型（可选：面试/门槛展示强化） | 0（本方案只改 Dify 后端） | 🟢 无风险 |

### 3.2 可能引入的回归风险 + 缓解措施

| 风险点 | 可能性 | 影响 | 缓解措施 |
|--------|--------|------|---------|
| 路由 Prompt 强化 both 后，原本纯 fact 查询被误判为 both（如「数学建模协会有什么活动？」被 both） | 中 | fact 类用例召回噪音 ↑ | 缓解：迭代 1 完成后，先跑 R-001~R-005（纯 fact）5 条单测，确认不回退 |
| QA 库硬植入关键词后，推荐逻辑过于依赖关键词，导致语义相似输入（如「我想做手工」）召回下降 | 低 | 新场景推荐退化 | 缓解：关键词植入采用「标题 + 首段摘要」方式，不替换原文；扩充 C-003 为 3 条同义输入做回归 |
| 历史拼接后，路由 Prompt token 超出上限 / 延迟增加 | 中 | 响应变慢、成本 ↑ | 缓解：历史拼接限制最近 3 轮 + 每轮截断为 200 字；监控 token 增幅 ≤ 20% |

## 四、验收退出标准（Definition of Done）

**必须全部满足，v2.0.1 才允许上线：**

1. ✅ 全量 47 条用例通过率 ≥ 90%（FAIL ≤ 5 条，且不含任何 P0）
2. ✅ 维度一（AI 核心逻辑）8 条用例全部通过（100%）
3. ✅ 维度零（路由）15 条用例全部通过（100%）——路由是基础能力，零容忍
4. ✅ 连续 3 次全量回归，结果一致（温度=0 稳定性验证）
5. ✅ Token 成本增幅 ≤ 20%（对比 v2.0.0 基线）
6. ✅ 平均响应时间增幅 ≤ 15%（历史拼接不阻塞用户体验）
7. ✅ 「Badcase 修复日志」Sheet 按实际改动补齐（每条改动对应 Before/After/改动文件/根因分类四列）
